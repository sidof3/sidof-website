The Banking Problem

Every bank and microfinance institution runs on the same hard problems: knowing exactly who a client is, moving money correctly and provably, and giving every action an unambiguous owner.

Financial institutions — from single-branch microfinance lenders to multi-region banks — require that money is always accounted for, every sensitive action is traceable to a real person, and client access respects institutional hierarchy. Most small-scale banking software skips these guarantees to ship faster or bolts them on later as a costly rework.

The MicroFin Solution

MicroFin Manager was designed around these core financial guarantees from day one:

  • Immutable Ledger: Money is recorded on a permanent, append-only ledger. Mistakes are corrected via visible reversing entries, never silent edits.
  • Shared Maker-Checker Engine: High-risk tasks (account opening, loan approval, unblocking) mandate sign-off from a second authorized user before executing.
  • Strict Client Separation: Individual and Corporate clients have custom validation rules rather than a shared form with a checkbox.

Engineering Approach

Built on Java 21 and Spring Boot 3, with PostgreSQL as the system of record. The backend enforces a strict layered architecture (Controllers -> Services -> Repositories -> DTOs) so business logic remains centrally governed and database entities never leak into API contracts.

On the frontend, Angular 18+ with Angular Signals is used for fine-grained reactive state handling, reducing rendering overhead when updating complex accounting grids and live transaction logs.

Security Architecture Highlights
  • Multi-factor / One-Time Passcodes (OTP) for account step-up verification.
  • Automated lockout policies after repeated failed access attempts.
  • Individual token revocation (JWT blacklisting) for immediate session termination.
